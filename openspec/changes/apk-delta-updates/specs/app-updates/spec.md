# Spec Delta

## Purpose

定义 zoneu 的应用内更新行为：如何发现新版本、优先用补丁还是全量、下载与校验什么、
什么条件下才交给系统安装器，以及发布侧必须提供哪些资产才让这条链路成立。

## ADDED Requirements

### Requirement: 更新检查的时机与呈现

系统 SHALL 只在用户主动操作或进程启动时的提醒中联网检查更新，不得后台轮询。
检查失败时自动提醒 MUST 静默，设置页 MUST 如实显示可行动的原因。
debug 构建 MUST 不参与应用内更新（与 release 签名不同，下载的包必然装不上）。

#### Scenario: 启动提醒发现新版本

- **WHEN** release 构建启动且远端存在比本机新、用户未跳过的版本
- **THEN** 弹出一次提醒，提供"更新"与"跳过此版本"；关掉弹窗不算跳过

#### Scenario: 检查失败

- **WHEN** 检查更新时网络不可达或响应无法解析
- **THEN** 不弹提醒；设置 → 版本更新 显示失败原因，且该原因指向用户能采取的动作

#### Scenario: debug 构建

- **WHEN** 当前是 debug 构建
- **THEN** 不自动检查、不提供应用内更新入口

### Requirement: 全量更新的来源与完整性

全量更新 MUST 只使用 release 中与 `.sha256` 配对的 APK 资产；二者缺一即视为没有可用更新。
下载完成 MUST 校验整包 SHA-256，并 MUST 比对下载包的签名证书与当前安装包的签名证书；
任一不符 MUST 作废该文件且不交给安装器。

#### Scenario: 哈希不符

- **WHEN** 下载完成的字节与 release 里的 `.sha256` 不符
- **THEN** 丢弃该文件，向用户显示失败原因，不提供安装入口

#### Scenario: 签名不符

- **WHEN** 下载包的签名证书与当前安装包不一致
- **THEN** 拒绝安装并丢弃该文件

#### Scenario: 缺少哈希资产

- **WHEN** release 里只有 APK 而没有对应的 `.sha256`
- **THEN** 按"已是最新"处理，不下载任何字节

### Requirement: 补丁优先的兼容判据

系统 SHALL 在下列判据全部成立时使用补丁，否则 MUST 使用全量：
补丁清单存在、清单格式号被本机认识、本机版本在清单中、本机已安装包的字节与清单记录的
基线哈希相符、补丁文件哈希相符、剩余空间足够、应用后的产物通过整包校验。

#### Scenario: 命中窗口且基线相符

- **WHEN** 本机版本在清单内，且本机已安装 APK 的 SHA-256 等于清单的基线哈希
- **THEN** 下载补丁并应用，而不是下载全量包

#### Scenario: 基线字节不符

- **WHEN** 本机版本号在清单内，但已安装 APK 的 SHA-256 与清单基线不符（重发过 tag、换了签名材料、从别处安装）
- **THEN** 不下载补丁，直接走全量

#### Scenario: 清单格式不认识

- **WHEN** 清单的格式号高于本机支持的版本
- **THEN** 忽略补丁，直接走全量

#### Scenario: 本机版本不在窗口内

- **WHEN** 本机版本早于清单覆盖范围
- **THEN** 直接走全量

### Requirement: 补丁路径的失败语义

补丁路径上的任何失败 MUST NOT 呈现为"更新失败"：系统 SHALL 静默转为全量下载。
补丁产物 MUST 通过与全量相同的整包 SHA-256 与签名证书校验后才可交给安装器。

#### Scenario: 产物校验失败

- **WHEN** 补丁应用后的整包哈希或签名与预期不符
- **THEN** 丢弃产物，界面转为"正在下载完整包"，不显示错误

#### Scenario: 补丁下载或应用中断

- **WHEN** 补丁下载中断或应用过程抛错
- **THEN** 清理补丁与半成品，转为全量下载

### Requirement: 断点续传与取消

下载 MUST 支持跨进程续传，用 `If-Range` 而非裸 `Range` 判断服务器上那份是否仍是同一文件；
服务器返回 206 时 MUST 把剩余长度加回已落盘偏移得到总长；返回 416 时 MUST 丢弃本地半截文件
去掉 Range 重新请求。取消 MUST 视为暂停：半截文件与边车保留，下次从断点继续。
续传 MUST NOT 放松整包校验。

#### Scenario: 中断后继续

- **WHEN** 下载被取消或进程被杀后用户重新点更新
- **THEN** 从已落盘长度接着下，进度条从该位置开始而不是从 0 开始

#### Scenario: 服务器上的同名文件已换

- **WHEN** 续传请求的 `If-Range` 判定服务器上的文件已变化
- **THEN** 丢弃本地半截文件整份重来，不拼接两份不同的字节

#### Scenario: 本地比服务器长

- **WHEN** 服务器对续传请求返回 416
- **THEN** 丢弃本地半截文件，去掉 Range 重新请求一次

### Requirement: 下载物的存储与清理

系统 MUST 只保留当前目标版本的半截文件与边车，其它版本残留 MUST 在下次下载前清理。
已下载并交给系统安装器的包 MUST 在**安装生效后的下一次启动**清理，而不是交付时立即删除
（安装器仍在读该文件）。

#### Scenario: 安装完成后再启动

- **WHEN** 更新已安装生效，应用再次启动
- **THEN** cacheDir 中该次更新下载的包被删除，不再占用空间

#### Scenario: 用户在安装器中放弃

- **WHEN** 用户在系统安装器里取消安装并返回应用
- **THEN** 已下载并校验过的包保留，"安装"仍可直接使用，不重新下载

### Requirement: 发布侧的补丁契约

每个 release MUST 发布全量 APK 及其 `.sha256`，并 SHALL 发布补丁清单与"最近 6 个应用版本 → 本版"
的补丁。补丁 MUST 基于**已发布签名产物**生成，不得基于构建中间物。
补丁资产与清单 MUST 不可变：重发同一 tag 时必须重算并替换。
补丁生成或验证失败 MUST NOT 阻断发布，但该补丁 MUST NOT 发布，且必须在发布说明中记录原因。

#### Scenario: 正常发布

- **WHEN** 打 `v*` tag 并完成构建
- **THEN** release 包含全量包、清单、以及窗口内每个可用版本到本版的补丁与各自的哈希

#### Scenario: 补丁往返验证失败

- **WHEN** 用旧包应用生成的补丁后得到的字节与新版 APK 的 SHA-256 不符
- **THEN** 该补丁不上传，发布继续，发布说明写明补丁缺失

#### Scenario: 重发同一 tag

- **WHEN** 需要重新发布一个已存在的 tag
- **THEN** 该 tag 的补丁与清单随新产物重算，不沿用旧补丁

### Requirement: 发布产物的可复现性

同一份源码连续两次装配出的运行时归档 MUST 逐字节相同（固定时间戳与条目顺序、不写额外字段）。
该性质是补丁有效性的前提，CI MUST 以"连续两次装配比较哈希"的方式校验它。

#### Scenario: 连续两次装配

- **WHEN** 在同一份源码上连续执行两次运行时装配
- **THEN** 两次产物的 SHA-256 相同

#### Scenario: 可复现性被破坏

- **WHEN** 装配脚本引入新的不确定性（时间戳、顺序、随机字段）
- **THEN** 可复现性门禁失败，CI 报错并指出产物哈希不同
